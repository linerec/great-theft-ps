# Languages: English and Korean

Written 2026-11-26. The app is English by default and can be switched to Korean (the button in the header, a block in the
settings, a link in the login box, or `?lang=ko` in the address). The choice is kept in this browser (`gtp.lang`); nothing
is chosen from the browser's own language, so a new visitor sees English.

## How it is built

English is what the code says; Korean is a dictionary beside it, **keyed by the English sentence**. A sentence is written
once, where it is used, and a reader of the code sees what a person sees.

| Where | How |
|---|---|
| code of the page | `t('Connected to {name}', { name })` (`src/i18n/index.ts`): the language of the page, `{name}` filled in |
| a table of words (kept, shown later) | `N_('Same network, at home')` in the table, `t(x)` where it is shown |
| `web/index.html` | English in the page; `data-i18n` on the element (its content, with inline markup, is the sentence), `data-i18n-attr="title aria-label"` for attributes. `web/lang.ts` puts the language in |
| the bridge (many people at once) | `translate(lang, 'English sentence', vars)` with the language the page said in its `hello` message (`lang`; anything else is English) |
| a report made in a worker | the language is handed to it (`formatReport(report, lang)`); the CLI has `--lang ko` |
| Korean | `src/i18n/ko-*.ts` (one part per area; `ko.ts` joins them) |

A sentence is one string literal: no joining with `+`, no `${}` (use `{name}`), no other braces, no plural tricks. Words that
are put on the page once and kept (set at start, or after a one-off event) are drawn again on a change of language: subscribe
with `onLang(...)` (or the `gtp:lang` event). A table or constant at module level must not call `t()`: it would freeze the
language when the file loads.

## What keeps it honest

`test/i18n.test.ts` reads the code and the page: every sentence has Korean, no Korean is left for a sentence that is gone
(so changing an English sentence without its Korean fails), the `{pieces}` match in both languages, no part of the
dictionary translates a sentence differently from another, and **no Hangul is written anywhere in `web/` and `src/` outside
`src/i18n/`**, comments included. At run time a missing Korean sentence shows in English and is remembered in
`missingKeys()`; the page's self-test (`npm run e2e`) switches to Korean, visits the panels and the study, and fails if
anything was missing. Server messages are tested in both languages (`test/ps5-link.test.ts`, `test/bridge-lang.test.ts`).

## Not done

Text that was made once in one language stays in it until it is made again: the reason a connection closed
(`BridgeClient.detail`), the server's `error` messages, a profile error already shown. Notes in the docs are English; the
Korean dictionary is the only place Korean lives.
